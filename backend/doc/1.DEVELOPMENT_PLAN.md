o# Resume Intelligence Platform — Development Plan

> Stack: Spring Boot + Spring AI + OpenAI GPT-4o + React + Vite + TailwindCSS

---

## Core Product (MVP — Must Demo)

### Features
1. **PDF Upload** — user uploads their resume PDF
2. **ATS Score** — section-wise score breakdown (ATS keywords, skills, projects, impact, role alignment)
3. **Skill Extraction & Gap Analysis** — extracted skills vs a chosen target role
4. **Role Eligibility** — which job titles the candidate fits, ranked by match %
5. **Improvement Suggestions** — bullet-by-bullet before/after rewrites shown in UI

---

### Backend Development Plan

**Setup**
- Spring Boot 3.x project with dependencies: `spring-ai-openai-starter`, `pdfbox`, `jackson`, `spring-web`
- `application.yml` with OpenAI API key + model config (`gpt-4o`)
- CORS config for React frontend

**Services to build**

| Service | What it does |
|---|---|
| `ResumeParseService` | Extracts plain text from uploaded PDF using Apache PDFBox |
| `AIAnalysisService` | Orchestrates all OpenAI calls in sequence |
| `ScoringService` | Parses ATS score JSON from OpenAI, structures section breakdown |
| `SkillGapService` | Loads role catalogue from JSON files, computes skill overlap, calls OpenAI for gap detail |
| `JobMatchingService` | Compares candidate skills against JD corpus, ranks roles by match % |
| `ImprovementService` | Calls OpenAI for bullet-by-bullet improvement suggestions |

**OpenAI Calls (all return structured JSON)**

| Call | Input | Output |
|---|---|---|
| Profile Extraction | raw resume text | `{ name, skills[], experience[], projects[], education[] }` |
| ATS Scoring | raw resume text | `{ totalScore, sections: { ats, skills, projects, impact, roleAlignment }, strengths[], issues[] }` |
| Skill Gap | candidate skills + target role | `{ strong[], partial[], missing[], priorityLearning[] }` |
| Improvement | resume text + weak sections | `{ suggestions[{ original, improved, reason }] }` |

**Data files (no DB — plain JSON/text in `/resources`)**
- `/resources/roles/` — role definitions with required + preferred skills (~10–15 roles)
- `/resources/jd-corpus/` — 30–50 JD text files for skill matching

**Where AI (GPT-4o) is used**

| # | Where | What AI does |
|---|---|---|
| 1 | Profile Extraction | Reads raw resume text, outputs structured JSON (name, skills, experience, projects) |
| 2 | ATS Scoring | Scores the resume section-by-section with reasons and evidence |
| 3 | Skill Gap Analysis | Given candidate skills + a target role, explains what's missing and why it matters |
| 4 | Improvement Suggestions | Rewrites weak bullet points into stronger, quantified, action-verb-led versions |

Everything else — role match %, skill overlap calculation, JD corpus lookup, tab rendering — is plain Java/React logic. No AI needed.

---

**REST API Endpoints**

```
POST  /api/resume/upload           → upload PDF, get sessionId + parsed text
POST  /api/analyse/full            → run full analysis pipeline, returns all results
GET   /api/analyse/{id}/score      → ATS score breakdown
GET   /api/analyse/{id}/skills     → skill extraction + gap
GET   /api/analyse/{id}/roles      → matched role eligibility list
GET   /api/analyse/{id}/improve    → improvement suggestions
```

### Frontend Development Plan

**Setup**
- Vite + React + TailwindCSS + Axios
- React Context for passing analysis result across tabs

**Pages / Components**

| Component | What it shows |
|---|---|
| `Landing` | Upload PDF button, brief product tagline |
| `UploadPanel` | Drag-drop file input, loading state with step progress |
| `Dashboard` | Tab container (Score / Skills / Roles / Improve) |
| `ScoreTab` | Circular total score + section score bars with feedback text |
| `SkillsTab` | Skill chips (green = have, orange = partial, red = missing), gap list per selected role |
| `RolesTab` | Role cards with match % bar, click to set target role for skill gap |
| `ImproveTab` | Before/after bullet list — original vs AI-improved version |

**Key UI details**
- Loading screen shows steps: "Parsing resume → Scoring → Analysing skills → Done" so it feels alive
- Roles tab: user clicks a role → SkillsTab updates to show gap for that role
- ImproveTab: each suggestion card shows original (red), improved (green), and reason
